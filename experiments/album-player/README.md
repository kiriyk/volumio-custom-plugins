# Album Player: временный эксперимент

Проверка ARM32 Album Player и его UPnP-рендерера на существующем Volumio.
Это исследовательские скрипты, не устанавливаемый плагин и не реализация
переключателя движков. Результаты: `docs/research/2026-11-11-album-player.md`.

## Что требуется

- Raspberry Pi с armhf, Python 3, `unshare`, `mount`, `strace`, доступом sudo.
- Работающий установленный Qobuz Custom с авторизованным аккаунтом.
- Доступный трек 8767428; для второго потока выполняется поиск
  `Give Life Back to Music`, поэтому выбранная запись может измениться.
- Свободные порты 7778/7779. UPnP-порт рендерера назначается динамически.
- UID/GID пользователя volumio — 1000; скрипт использует это явно.

## Размещение и запуск

В **отдельный** `/tmp/albumplayer-research` распаковать официальные архивы
`https://albumplayer.ru/linux/aplayer-arm32.tar.gz` и
`https://albumplayer.ru/linux/aprenderer-arm32.tar.gz`. Скопировать туда
четыре Python-файла из этого каталога, сохранив имена. Не использовать каталог
с установленным пользовательским плеером.

Запускать на Pi:

```sh
sudo python3 /tmp/albumplayer-research/isolate.py probe.py
sudo python3 /tmp/albumplayer-research/isolate.py renderer-probe.py
```

`isolate.py` сам создаёт отдельное пространство монтирования, подменяет
`/etc/asound.conf` на ALSA null только в нём, скрывает `/dev/snd` и сбрасывает
права до UID/GID 1000. Сеть общая с Pi: тесты обращаются к локальному посреднику
Qobuz и временным API плееров. Штатные службы не останавливаются.

`probe.py` проверяет API локального плеера, загрузку папки, профили обработки
и передачу потокового URL через радиорежим. `renderer-probe.py` проверяет
профили, SOAP-команды, seek, следующие URI и явную смену трека.

Перед/после снимаются хеш `playlistinfo` и основные поля состояния MPD.
Сценарий предполагает, что пользователь в это время не меняет очередь.

## Ограничения и данные

ALSA null не воспроизводит поведение физического DAC. Эти проверки не
подтверждают bit-perfect, бесшовность или отсутствие щелчков.
Успех SOAP-команды сам по себе не считается подтверждением воспроизведения.
Скрипты выводят фактические наблюдения; отдельные поля `false` означают
неподтверждённый сценарий, даже если процесс Python завершился с кодом 0.

Ключ посредника читается только локально на Pi и не выводится. Временные
файлы `stream.m3u`, радиостанции и сетевой trace содержат временные URL;
их нельзя публиковать. Сохранять можно проверенные `summary.json` и
`renderer-summary.json`, в которых нет URL и ключей.

После проверки остановить только процессы из этого тестового каталога и
удалить его. Скачанные сторонние бинарники в репозиторий не включаются.


## Приёмка транспорта через настоящий код очереди

`queue-acceptance.js` и `queue-isolate.py` используют отдельный каталог
`/tmp/albumplayer-transport-test`. В нём ожидаются распакованный `aprenderer/`,
`acceptance.js`, а также `code/` с `shared/playback`, `qobuz/lib` и установленной
XML-зависимостью из корня репозитория. Подготовка использует настоящий
`/volumio/app/statemachine.js` с приватной копией `/data/queue` в mount namespace.
Снимки основной очереди делаются отдельным `primary-snapshot.py` вне namespace.

Стенд передаёт реальные URL Qobuz через локальный HTTP-посредник с ограничением
скорости, чтобы null-выход не завершал трек мгновенно. Для полного прогона файл
`/tmp/albumplayer-transport-test/smoke` отсутствует. Его наличие включает короткий
прогон на двух треках. Треки ускоренно завершаются через seek к концу.
Результаты без URL: `queue-result.json` и `queue-smoke-result.json`.
