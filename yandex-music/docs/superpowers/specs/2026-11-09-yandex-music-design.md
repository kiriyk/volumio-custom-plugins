# Яндекс Музыка для Volumio 4: первая рабочая версия

Статус: принят к реализации указанием пользователя «Продолжай реализовывать».
Дата: 2026-11-09.

## Назначение и договорённости

Нативный источник `music_service/yandex_music` для личного плеера на Raspberry Pi 4
с 4 ГБ RAM. Вход, поиск, собственная коллекция и воспроизведение доступны из
существующего интерфейса Volumio, в том числе с телефона. Отдельного сайта нет.

Пользователь выбрал полноценную первую версию вместо демонстрационного каркаса
и исключил «Мою волну». Он сообщил об установке Volumio 4 и повторном включении
SSH. До обновления на устройстве были Volumio 3.912, Node 14 и Python 3.7;
эти сведения больше не считаются характеристиками целевой системы.

Репозиторий создан отдельно в `volumio-yandex-music/`, ветка `main`.
Все решения ниже, не названные договорённостями, — предложения разработчика,
которые пользователь может изменить при согласовании документа.

## Целевая система и проверка совместимости

- Volumio 4 на Bookworm; Node.js >= 20; Python >= 3.11 как целевой runtime проекта.
- Архитектуру определяем по `dpkg --print-architecture`, а не только `uname -m`:
  у Raspberry Pi возможен 64-битный kernel с 32-битным userspace.
- Перед кодом playback прочитать реализацию `music_service/mpd`, state machine
  и маршрутизацию музыкальных сервисов именно установленного backend.
- Зафиксировать версию Volumio, runtime, архитектуру и использованные сигнатуры
  в `docs/compatibility.md`. Установщик проверяет эти ограничения до изменений.
- SSH к обновлённому устройству проверен: `volumio@volumio.local`,
  `192.168.1.105`. Подтверждены Volumio 4.239 / Bookworm, Node 20.5.1,
  Python 3.11.2, userspace `armhf`, MPD 0.24.6. Результаты чтения backend
  и ограничения проверки записаны в `docs/compatibility.md`.

## Первая версия

1. Установка, включение, отключение и удаление штатным механизмом плагинов.
2. Настройки на русском и английском; статус Python-сервиса и аккаунта.
3. Один аккаунт: вход по коду устройства, сохранение сессии, выход.
   Ручной ввод готового OAuth-токена — запасной способ, без ввода пароля Яндекса.
4. Поиск треков, альбомов, исполнителей и плейлистов с постраничной навигацией.
5. Коллекция: понравившиеся треки, собственные и сохранённые плейлисты,
   избранные альбомы и исполнители. Эти разделы в первой версии доступны на чтение.
6. Страницы плейлиста, альбома и исполнителя; обложки, названия, длительность.
   Для исполнителя показываем доступные популярные треки и альбомы, а не обещаем
   неограниченную полную дискографию одним запросом.
7. Очередь Volumio: одиночный трек, воспроизведение/добавление альбома или
   плейлиста, play/pause/stop, previous/next, seek, корректные метаданные.
8. Понятные ошибки авторизации, подписки, недоступного контента и сети.

По качеству предлагается MP3 до 320 кбит/с при его доступности. AAC разрешён
только после проверки фактического контейнера и декодирования установленным MPD.
Выбранное качество отражает реально полученный файл; доступность не обещается
для каждого аккаунта и трека. Повторного сжатия и ресемплинга в плагине нет.

Не входят: «Моя волна», рекомендации и autoplay, FLAC/encraw, локальное
скачивание музыки, редактирование коллекции, синхронизация с приложением Яндекса,
мультиаккаунт, энкодер и отдельный frontend. Управление с телефона означает
использование интерфейса Volumio. FLAC остаётся следующим расширением адаптера.

## Рассмотренные подходы

### A. Node.js + постоянный Python/aiohttp-сервис под systemd — предлагается

Node занимается только контрактом Volumio. Python использует `yandex-music`
для авторизации и каталога и обслуживает локальный поток. Постоянный процесс
переиспользует HTTP-соединения и состояние входа; systemd отвечает за перезапуск.
Цена — два runtime и необходимость связать жизненный цикл с плагином.

### B. Node.js + постоянный дочерний Python-процесс

Меньше файлов systemd, процесс удобно запускать из плагина. Но обработка смерти
родителя, потерянных дочерних процессов и перезапусков становится нашей задачей.
Для сервиса на устройстве systemd проще сопровождать.

### C. Node.js с запуском Python для каждого запроса

Прост для разового запроса метаданных, но создаёт повторную инициализацию клиента
и не даёт единого владельца длительных потоков и незавершённого входа.
Как основа рабочего плагина не предлагается.

Подход A принят как предложенная разработчиком архитектура после указания
пользователя продолжать реализацию подготовленного проекта.

## Компоненты и границы

`index.js`, `package.json`, `config.json`, `UIConfig.json`, `i18n/`, `lib/` —
Node-адаптер. CommonJS JavaScript, зависимости в lock-файле. Наружные методы
возвращают совместимые с Volumio promise; при необходимости native Promise
преобразуется в `kew` на границе.

`service/` — Python-приложение: HTTP-слой aiohttp, auth manager, адаптер
`yandex-music`, нормализация данных, потоковый proxy и хранилище credentials.
Зависимости фиксируются; установка использует отдельный `venv`.

`systemd/`, `install.sh`, `uninstall.sh` — жизненный цикл и установка.
Сервис работает пользователем `volumio`, без доступа к ALSA: звук выводит MPD.
Порт по умолчанию 17899, только `127.0.0.1`; занятый порт даёт ошибку,
чужие процессы установщик не завершает. Два экземпляра плагина не поддерживаются.

Направления данных: интерфейс Volumio → Node → локальный Python → Яндекс;
аудио: Яндекс → Python → MPD → настроенный Volumio аудиовыход.
Изменений Volumio Core, глобальных Node/Python, ALSA и конфигурации MPD нет.

## Каталог и внутренний HTTP API

HTTP-контракт имеет префикс `/v1`, нормализованные DTO и единый формат ошибок.
DTO трека: `id`, `album_id`, `title`, `artists`, `album`, `duration_ms`,
`cover_url`, `available`; DTO страницы: `items`, `next_cursor`.
Схема фиксируется вместе с тестами до разработки двух адаптеров.

Набор ресурсов: `/health`, `/v1/account`, `/v1/auth/device`,
`/v1/auth/device/{session_id}`, `/v1/auth/token`, `/v1/auth/logout`,
`/v1/search`, `/v1/library/{section}`, `/v1/playlists/{owner}/{kind}`,
`/v1/albums/{id}`, `/v1/artists/{id}`, `/v1/tracks/{id}`,
`/v1/playback/resolve`, `/stream/{ticket}`.
HTTP-методы и тела операций фиксирует план реализации: чтение — GET,
вход, выход и создание билета — POST; у stream дополнительно HEAD.

Размер страницы по умолчанию 50, максимум 100. Если API возвращает сразу список
идентификаторов коллекции, Python выдаёт его страницами и получает полные
метаданные только для текущей страницы. Кэш метаданных ограничен по размеру и TTL,
очищается при выходе/смене аккаунта. Сырые SDK-модели и credentials Node не получает.

URI Volumio сохраняют идентификаторы, а не временные ссылки Яндекса:
`yandex_music/track/<id>`, `yandex_music/album/<id>`,
`yandex_music/playlist/<owner>/<kind>`, `yandex_music/artist/<id>`.
Идентификаторы и параметры экранируются; заголовки не используются как ключи.
`handleBrowseUri` обслуживает каталог, `search` — поиск, `explodeUri` — очередь.
`browseLibrary` и `getStreamUrl` не считаются обязательными без проверки backend.

При раскрытии альбома/плейлиста сохраняем порядок и повторные вхождения треков.
Недоступные треки пропускаем с уведомлением; полностью недоступный список даёт
ошибку. Большой плейлист собирается порциями с лимитами времени и объёма;
первый релиз ограничивает одну операцию добавления 2000 треками и сообщает о лимите,
не обрезая результат молча. Конкретную пагинацию SDK проверяем на fixtures и Pi.

## Авторизация и данные

Device Flow реализуется фоновым опросом с интервалом и сроком жизни от Яндекса.
Настройки показывают verification URL и короткий пользовательский код;
секретный `device_code` остаётся в сервисе. Повторный запуск входа отменяет
предыдущую попытку. Результаты: ожидание, успех, отказ, истечение, ошибка.
Вход не удерживает HTTP-запрос и не блокирует интерфейс.

После получения токена проверяется доступ к музыкальному API. При наличии
refresh token обновление выполняется через OAuth grant с одиночным запросом
обновления на аккаунт; механизм и ответы проверяются по документации и fixtures.
Без refresh token либо при отклонении обновления статус становится «нужен вход».
Сетевой сбой не уничтожает рабочие credentials и не выдаётся за неверный пароль.

Токены сохраняются атомарно в отдельном файле в
`/data/configuration/music_service/yandex_music/`, режим 0600, владелец volumio.
Общий ключ Node ↔ Python хранится отдельно с теми же правами; контрольные HTTP
запросы требуют его в заголовке. `/health` без авторизации отдаёт только версию
контракта и готовность локального процесса. Токены не возвращаются в настройки,
не кладутся в `config.json`, репозиторий, URL или логи.

Выход очищает credentials, кэш, попытку входа и stream tickets; останавливает
только текущее воспроизведение этого источника. Удалённый OAuth-токен по одному
локальному выходу не считается отозванным у Яндекса.

## Воспроизведение

Перед началом каждого трека `clearAddPlayTrack` разрешает стабильный ID через
Python и передаёт локальный URL штатному MPD-адаптеру. Сигнатуру передачи,
обновление state machine, pause/resume/seek и источник событий окончания
сверяем с установленным backend перед кодом playback. В очереди остаётся
`service: yandex_music`; плагин не подменяет её истекающими внешними URL.

В проверенной state machine вызов `clearAddPlayTrack` не ожидает возвращённый
Promise. Адаптер самостоятельно обрабатывает ошибки асинхронного разрешения,
уведомляет пользователя и восстанавливает корректное состояние. Поздний ответ
предыдущего запроса не запускает музыку после stop/next/смены источника:
нужна отмена либо проверка поколения playback-запроса.

Stream ticket — случайный непрогнозируемый идентификатор, привязанный к треку,
выбранному файлу и текущему аккаунту. Живёт в памяти процесса до 12 часов,
при выходе/остановке сервиса немедленно аннулируется. Наш код не логирует URL
tickets. Установленный MPD-адаптер Volumio пишет переданный URI на verbose;
поэтому отсутствие локального stream URL во всех логах Core не обещается.
В локальном URL нет OAuth-токена и подписанной ссылки Яндекса, а сам endpoint
доступен только с loopback устройства.
После перезапуска сервиса следующий запуск трека получает новый ticket;
пауза/продолжение со старым билетом может потребовать повторного запуска трека.
Размер таблицы билетов ограничен, просроченные записи удаляются.

Proxy читает и отдаёт данные порциями с ограниченным буфером, учитывает медленного
потребителя и закрывает upstream при отключении MPD. Трек целиком в память или
на SD не загружается. Произвольный внешний URL через API передать нельзя;
источники и перенаправления проверяются адаптером перед соединением.

Для перемотки поддерживаются одиночные HTTP Range, HEAD, Content-Type,
Content-Length и статусы 200/206/416. Диапазоны не эмулируются неверным ответом
200. Конкретный upstream обязан поддерживать выбранный путь seek: это условие
приёмки, а не обещание на основании одной сигнатуры SDK.

Истёкшую ссылку Яндекса разрешаем заново максимум один раз до отправки тела.
После начала отдачи не склеиваем разные файлы и не повторяем запрос незаметно;
ошибка закрывает поток и отображается через доступный механизм Volumio.
Расширение FLAC добавит отдельный resolver/decryptor, не меняя ID очереди;
расшифровка, смещения и seek FLAC потребуют самостоятельной проверки.

## Жизненный цикл и установка

`install.sh` проверяет среду, устанавливает только необходимые системные пакеты
для venv/сборки зависимостей, создаёт venv и unit. Версии runtime не обновляются.
На проверенном Pi установлен pip, но отсутствуют `python3-venv` и
`python3.11-venv`: установщик должен добавить пакет venv либо явно завершиться
с понятной ошибкой до развёртывания сервиса.
Установка не запускает музыку и не включает сервис автоматически через systemd:
его владельцем остаётся включённый плагин Volumio.

`onStart` запускает свой unit, ограниченно ждёт локальный healthcheck,
проверяет версию HTTP-контракта, затем регистрирует источник. Наличие входа или
интернета не обязательно для включения: без аккаунта источник объясняет вход.
`onStop` удаляет источник, очищает таймеры/запросы и останавливает только свой unit.
При падении Python systemd перезапускает его с ограничениями частоты;
Node возвращает ограниченные по времени ошибки, интерфейс остаётся отзывчивым.

Установка на Pi: скопировать release-каталог, перейти в него,
выполнить `volumio plugin install`, затем включить плагин в UI и войти в аккаунт.
Артефакт не содержит `.git`, тестовых секретов, venv с другой архитектуры
или `node_modules`, собранных под другой runtime. Повторная установка сохраняет
credentials; перед обновлением сохраняется предыдущий release для отката.

`uninstall.sh` останавливает и удаляет только собственный unit и runtime.
Сохранённые credentials удаляются при uninstall; поведение конфигурационной
директории дополнительно согласуется с реальным plugin manager, чтобы не оставить
копий токена. Обновление должно быть отличимо от полного удаления плагина.
Системные зависимости, которые могут использовать другие компоненты, не удаляются.

## Ошибки и наблюдаемость

Единые коды: `AUTH_REQUIRED`, `AUTH_EXPIRED`, `ACCESS_DENIED`, `NOT_FOUND`,
`UNAVAILABLE`, `RATE_LIMITED`, `UPSTREAM_TIMEOUT`, `SERVICE_UNAVAILABLE`.
Пустая коллекция/поиск — успешный пустой результат, а не ошибка.
Для 429 учитываем Retry-After; read-only запрос можно ограниченно повторить.
Вход, очередь и другие операции с побочными эффектами автоматически не повторяем.
Время запросов ограничено; размеры запросов и параллелизм также ограничены.

Логи содержат операцию, correlation ID и безопасный код ошибки.
Сырые исключения SDK, заголовки авторизации, тела OAuth и URL Яндекса
с подписью не записываются. Режим DEBUG также не включает их. Ограничение
логирования локального stream URL в Volumio Core описано выше.

## Проверка и приёмка

1. Node unit-тесты с подставным commandRouter: регистрация/удаление источника,
   Promise-контракты, поиск, каталог, очередь, метаданные и маршрутизация ошибок.
2. Python unit-тесты с fixtures: коллекции, пустые/частичные ответы,
   недоступные треки, пагинация, Device Flow pending/expiry/cancel, refresh,
   атомарное сохранение и очистка credentials.
3. Проверка HTTP-контракта: настоящий Node-клиент → настоящий aiohttp-сервис
   с подставным адаптером Яндекса. Реальные HTTP-статусы, таймауты, отказ в доступе.
4. Проверка proxy с локальным upstream: идентичность переданных байтов,
   GET/HEAD/Range и 416, обрыв потребителя, истёкшая ссылка, медленный поток.
   Тестовый большой поток генерируется порциями; тест ловит чтение целиком и
   рост буфера с размером файла, а не фиксирует выдуманное потребление RAM.
5. Проверки пакета: JSON, shell syntax, фиксированные зависимости,
   отсутствие секретов и чужой архитектуры в release.
6. На настоящем Pi: install/enable/disable/reboot/uninstall, ручной вход
   владельцем аккаунта, реальный поиск и все разделы коллекции, обложки с телефона.
7. На настоящем Pi с аккаунтом: play/pause/resume, previous/next, seek вперёд
   и назад, естественный переход к следующему треку, старые элементы очереди,
   временный обрыв сети, перезапуск Python и смена источника.
8. На Pi: после прогрева 30 минут воспроизведения наблюдать RSS, CPU, отсутствие
   OOM и роста памяти по длине треков. Приёмка RAM/CPU — фактический отчёт, а не
   неподтверждённое сравнение с Volumio 3.

Автоматические тесты работают без реального аккаунта и интернета. Live-тесты
отдельные и явно запускаются с локальными credentials. Тесты на ПК не заменяют
проверку реального MPD, GUI и установщика. «Полностью работает» заявляем только
после аппаратной приёмки, а не после прохождения mock-тестов.

## Что решает разработчик при планировании

Точное разбиение модулей, тестовый runner Node, схема фикстур, границы кэшей,
HTTP timeouts, разрешённые домены upstream, retry/backoff, refresh HTTP-адаптер,
упаковка зависимостей под armhf и конкретная интеграция с проверенным MPD API.
Изменение обязательных пользовательских функций и переход на другой playback
engine требуют возврата к обсуждению. Невозможность Device Flow не скрывается:
используется явно описанный запасной вход по токену.

Документация не заменяет чтение установленного backend. Часть сигнатур уже
подтверждена на Pi; полный маршрут состояний, завершения трека и восстановление
после ошибок требуют дальнейшей проверки и аппаратных тестов. Playback пока
остаётся проектом, а не подтверждённой работающей интеграцией.
