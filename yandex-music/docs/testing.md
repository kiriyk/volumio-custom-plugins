# Проверка плагина

Автоматические тесты выполняются без аккаунта Яндекса и интернета.
Python: `uv run pytest -q`. Node и настоящий Node → Python HTTP-контракт:
`npm test` (предварительно `uv sync` создаёт `.venv`).

Проверяются: приватное хранение credentials, Device Flow/cancel, безопасные
ошибки, DTO и порядок коллекции, control API, stream GET/HEAD/Range,
переполучение истёкшей ссылки, queue mapping, отмена playback при смене
источника/stop, жизненный цикл и пакет без секретов/чужого venv.
Shell-установщик выполняется в staging root с подставными системными командами;
проверяется отказ preflight, сохранение входа на update и удаление собственных данных.

## Аппаратная приёмка 2026-11-09

На Raspberry Pi 4 / 4 ГБ, Volumio 4.239 установлен и включён релиз **0.1.5**.
Проверки ниже выполнены по SSH и через реальный Web UI. Аккаунт подключён
владельцем через Device Flow; токены в отчёт и репозиторий не копировались.

| Проверка | Результат |
| --- | --- |
| Установка | Штатный `volumio plugin install`, зависимости armhf, отдельный venv; 37 новых apt-пакетов, без обновления системных пакетов |
| Жизненный цикл | Disable → enable, удаление → повторная установка до входа; при отключении останавливается собственный systemd unit |
| Обновление | Полное обновление до 0.1.5 через API Volumio, сохранён вход и права 0600; после перезапуска Volumio загружен новый Node-код |
| Авторизация | Вход по коду устройства подтверждён; аккаунт сохранился после перезапусков Python и Volumio service |
| Каталог | Реальные liked tracks, собственные и сохранённые плейлисты, избранные альбомы и исполнители; переход внутрь альбома, плейлиста и исполнителя |
| Поиск | Запрос Radiohead через Volumio вернул четыре группы: треки, альбомы, исполнители, плейлисты |
| Очередь | Реальный плейлист развёрнут в 17 доступных треков; недоступные позиции пропущены |
| Поток | Реальный MP3 320 кбит/с: HEAD 200, размер 7 387 428 байт; Range 0–1023 → 206 и ровно 1024 байта |
| MPD | Play, pause, resume, seek на 30 секунд, next, previous и автоматический переход в конце трека; стабильный URI и метаданные Яндекса в state |
| Stop | Остановка подтверждена непосредственно командой status MPD, а не только состоянием UI |
| Мобильный UI | Настройки и коллекция открыты в браузере 390 × 844; обложки и длительности отображаются, поле токена пустое |

Для MPD подтверждён маршрут через `consumeUpdateService('mpd', true, false)`.
У реального CDN встречаются redirect 308 на `*.strm.yandex.net` и MIME
`application/octet-stream`; MPD распознаёт MP3 и воспроизводит его.
В тесте временно устанавливалась громкость 15; затем восстановлена исходная 86,
тестовая очередь очищена. Субъективная проверка слышимого звука владельцем
в автоматическую приёмку не входит.

Фоновая проверка ресурсов выполняется отдельно от аудиовыхода: реальный поток
читается небольшими порциями со скоростью 320 кбит/с. Она не управляет очередью,
громкостью или воспроизведением владельца.

Итог прогона 18:20–18:50 МСК: 1800 секунд, 15 последовательных потоков,
71 809 622 байта, без ошибок. RSS Python: минимум 32 780 KiB, максимум
37 536 KiB (36,7 MiB), итог 36 452 KiB (35,6 MiB). Открытых дескрипторов:
7 в начале, 8 в конце. CPU сервиса: 5,82 секунды, в среднем 0,32% одного ядра.
Это ограниченное измерение, а не доказательство отсутствия любых утечек памяти.

Температура в трёх контрольных точках: 57,9 °C; `get_throttled=0x0` во всех
точках, частота CPU при измерении 1,5 ГГц. Итоговый load average:
0.00 / 0.00 / 0.02. В промежуточном 5-секундном замере CPU всей системы
занят на 1,66%, отдельно наблюдалось около 24–25% I/O wait. Причина I/O wait
не установлена; этот показатель не следует смешивать с вычислительной нагрузкой
плагина. Нагрузка длительного декодирования MPD и вывода на ЦАП не измерялась.

## Воспроизводимые аппаратные проверки

После копирования файлов `tests/live/` на Pi:

```bash
node /tmp/native_smoke.js read
# Требует остановленного проигрывателя с пустой очередью, временно включает звук:
node /tmp/playback_smoke.js
# Реальные CDN-потоки без вывода звука; пишет только счётчики ресурсов:
python3 /tmp/stream_soak.py --seconds 1800
```

`native_smoke.js` также поддерживает `enable`, `disable`, `uninstall`.
Последний удаляет плагин и вход — используйте его только при отдельном испытании
удаления, а не для обновления.

## Границы проверки

- Физическое выключение и включение Pi после авторизации не выполнялось;
  сохранение входа проверено перезапусками сервисов.
- Вход готовым OAuth-токеном и принудительное истечение refresh grant
  проверены автоматическими тестами; реальный вход выполнен по коду устройства.
- Разрыв сети, поздний ответ после смены источника и аннулирование старого
  stream ticket проверены изолированными HTTP/Node-тестами. Сеть владельца
  для этих испытаний не отключалась.
- Подписи групп поиска пока используют названия разделов коллекции
  («Мне нравится», «Мои альбомы» и т. п.); сами результаты приходят из поиска.

Чтение сигнатур backend описано в [compatibility.md](compatibility.md).
Контрактные тесты не гарантируют будущую стабильность неофициального Яндекс API.
