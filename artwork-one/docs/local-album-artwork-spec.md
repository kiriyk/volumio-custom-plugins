# Обложки и информация о локальной музыке в Artwork One

Первая версия обогащает локальную библиотеку Volumio 4.239 на Raspberry Pi. Artwork One показывает недостающие обложки на карточках альбомов и при воспроизведении. Справки появляются в блоке «Информация» при воспроизведении, на странице исполнителя и на странице альбома. Музыкальная библиотека открывается для чтения. Модуль поставляется в составе `user_interface/artwork_one`.

## Интерфейс

| Точка входа | Отображение | Когда запрашиваем |
| --- | --- | --- |
| Карточка локального альбома | Обложка | Карточка попадает в область просмотра |
| Экран воспроизведения | Та же обложка в плеере. В блоке «Информация» краткие справки об исполнителе и альбоме, год и лейбл при наличии | Обложка при смене альбома, справки при открытии блока. На телефоне блок открывается через «Ещё» → «Информация» |
| Страница исполнителя | Блок «Информация» с краткой справкой об исполнителе | Открытие страницы |
| Страница альбома | Обложка в шапке и блок «Информация» с краткой справкой об альбоме, годом и лейблом при наличии | Открытие страницы |

Показываем первый содержательный абзац справки обычным текстом со ссылкой на статью. Пустые поля скрываем. Если справок и фактов для блока нет, скрываем его содержимое. Во вкладке Info остаются переходы, жанр, число треков и сведения о треке. Для локальной записи новая справка заменяет прежний поиск сведений об исполнителе и альбоме. Названия и имена на экране берём из Volumio. Название из каталога используется для сопоставления.

Обложка и справка загружаются независимо от навигации и воспроизведения. До ответа видна штатная картинка или заглушка. Ответ применяется только к карточке, странице или записи воспроизведения с той же локальной идентичностью. Для стримингов действует текущий путь Artwork One.

## Входные данные и ключи

- Локальный альбом определяется по типу представления и URI Volumio. В каталоге `albums://` альбом может иметь `type: folder`, поэтому тип элемента сам по себе недостаточен. Для воспроизведения отдельно проверяем, что URI указывает на локальный файл или CUE-трек. `service: mpd` сам по себе недостаточен. Произвольные папки, плейлисты и радиостанции модуль пропускает.
- Сопоставляем карточку и воспроизведение через канонический локальный источник, директорию или CUE и исходные теги альбома. Для карточки используем штатный путь из `/albumart`, а при его отсутствии уточняем путь по результату browse. Для трека путь берём из состояния воспроизведения. Приводим штатные формы `music-library/USB/…`, `mnt/USB/…` и `/mnt/USB/…` к общей форме. Для многодискового альбома используем общую директорию, если её подтверждает карточка и совпадают теги альбома. При недостатке данных сохраняем независимые ключи.
- Исполнителя альбома берём из `albumartist`, если поле доступно, либо из поля исполнителя записи об альбоме Volumio. Для воспроизведения имя отдельного трека используется только при подтверждении той же атрибуции альбома. Альбом без указанного исполнителя получает только локальную обработку обложки. Для страницы исполнителя используем имя из текущей страницы Volumio.
- Ключ кэша обложки и сведений об издании учитывает локальную идентичность, исходное название и исходного исполнителя. Нормализованное название поиска не объединяет издания. Справку об исполнителе кэшируем по подтверждённому MusicBrainz ID и языку, успешное сопоставление имени храним отдельно. Для справки об альбоме используем MusicBrainz release-group ID и язык.

## Обложка

1. Проверить штатную обложку Volumio. Для CUE использовать уже реализованную нормализацию `src/core/albumartUrl.ts`. Успех требует декодируемого изображения. Штатные заглушки определяем по сигнатурам ответов нашего Volumio, включая случаи HTTP 200 с SVG или JPEG. Произвольные внешние URL из ответа интерфейса сервер не загружает.
2. Если рабочей обложки нет, проверить встроенную лицевую картинку локального аудиофайла. Для карточки взять первый доступный аудиофайл по порядку треков. Для CUE использовать связанный аудиофайл по данным локальной библиотеки. Для воспроизведения использовать тот же выбор, чтобы переход между треками не менял обложку. Читать только канонически разрешённые файлы из музыкальных каталогов Volumio. Проверять границы после разрешения симлинков, отклонять выход за корень и ограничивать время чтения и размер результата.
3. Если локальной картинки нет и указан исполнитель, запросить `front-500` у Cover Art Archive для подтверждённого `release`. Если у него нет лицевой обложки, использовать обложку подтверждённого `release-group`. При совпадении только с группой запрашивать сразу её обложку. При неоднозначном альбоме оставить штатную заглушку. [Cover Art Archive API](https://musicbrainz.org/doc/Cover_Art_Archive/API)

Для рабочего локального файла обложки сохраняем штатный URL Volumio. Загруженные и извлечённые изображения приводим к JPEG с длинной стороной не более 500 px и размером до 256 КиБ. Проверяем размер до и после обработки. Источник обложки храним вместе с идентификаторами сопоставления.

## Сопоставление и справки

1. Если в локальных тегах есть MusicBrainz ID, проверить сущность по нему. Иначе искать по исполнителю и полному названию. Для имени исполнителя сравнивать совпадения по имени и алиасам, при возможности использовать контекст подтверждённого альбома. При неоднозначности справку пропустить.
2. Если полного совпадения нет, нормализовать пробелы, пунктуацию и эквивалентные варианты написания вроде `+` и `&`. Разобрать распознаваемые пометки издания в конце названия, например `US Edition` или `Super Deluxe`. Хранить извлечённые признаки отдельно. Концертные пометки сохранять как признак типа записи. Концертный альбом требует соответствующего концертного релиза или группы.
3. Подтвердить группу совпадением исполнителя и названия с учётом нормализации. Если подходят несколько групп, использовать только однозначное совпадение по локальным данным. Рейтинг выдачи MusicBrainz используется для порядка рассмотрения. Для подтверждения издания использовать проверенный release ID либо уникального кандидата по каталожному номеру или штрихкоду, при необходимости уточняя страну, год и формат. Тип издания учитываем при отборе. Если кандидатов всё ещё несколько, имеем только совпадение с группой. [Поля поиска MusicBrainz](https://musicbrainz.org/doc/MusicBrainz_API/Search)
4. Для подтверждённого издания показывать год и лейбл этого издания. Если подтверждена только группа, показывать год первого выпуска с подписью «Первый выпуск». Сохранять доступный локальный год издания как отдельный факт. Для справки об альбоме и исполнителе использовать связанную статью Wikipedia через Wikidata. Язык справки соответствует языку интерфейса, а отсутствие статьи оставляет остальные найденные поля доступными.

Внешний запрос передаёт только данные, нужные для сопоставления, например имя, название и каталожный номер. Пути, имена файлов и содержимое тегов целиком остаются на Pi. Все запросы MusicBrainz из Artwork One проходят через одну очередь с указанным `User-Agent` и интервалом не менее одной секунды между началами запросов. [Лимиты MusicBrainz](https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting)

## Интеграция и контракт

- Серверный модуль запускается и останавливается с `plugin/artwork_one/index.js`. Зарегистрировать асинхронные endpoints Volumio через `addPluginRestEndpoint`: `artworkOneLocalMusicInfo` и `artworkOneMusicBrainz`. Клиент вызывает их через `POST /api/v1/pluginEndpoint`. Ответ получает вызвавший HTTP-клиент. Диск и сеть обслуживает плагин. Существующие функции MusicBrainz идут через ту же серверную очередь. При остановке удалить endpoints.
- Новый метод `getLocalMusicInfo` принимает `requestId`, `kind` (`album` или `artist`), `uri`, необязательный `locale` и список `fields` (`cover`, `albumInfo`, `artistInfo`). По умолчанию для справки используем язык из `language_code` Volumio. Для альбома `uri` может указывать на карточку, страницу или локальный трек. Сервер валидирует поля и подтверждает локальную сущность через данные Volumio. Имя и путь для чтения нельзя передавать как произвольные параметры.
- Ответ `artworkOneLocalMusicInfo` возвращает `requestId`, канонический ключ сущности и результат отдельно для каждого запрошенного поля. Статусы `found`, `notFound` и `temporaryError`. Для найденной обложки вернуть штатный URL Volumio либо ограниченный JPEG в Base64 и его идентификатор. Для справки вернуть текст, URL источника и, для альбома, год с типом `release` или `firstRelease`, лейбл при подтверждённом издании и MusicBrainz ID сопоставления. Поля без значения опускать. Неверный или неподдерживаемый запрос получает явную ошибку в ответе.
- Клиентский стор дедуплицирует запросы и создаёт `blob:` URL для полученных JPEG. Удалять URL при вытеснении из памяти. Подключить `MusicCard.tsx`, `NowPlaying.tsx`, `InfoFace.tsx`, `AlbumHead.tsx` и `ArtistHead.tsx`. Основная обложка, фон и обложка в Info при воспроизведении используют одно значение. Переиспользовать текущие `BrowseInfo` и состояние плеера для построения запроса. Для локальных альбомов в `src/core/store/about.ts` использовать новый результат для сведений об исполнителе и альбоме. Метаданные трека запрашивать по текущему контракту через серверную очередь.

## Дисковый кэш и ошибки

Хранить кэш под `/data` в отдельном каталоге данных плагина, вне каталога установленного интерфейса. Общий лимит **64 МиБ** с учётом файлов картинок и записей метаданных. Записи публиковать атомарно и удалять по времени последнего обращения. Очередь выполняет один активный запрос к MusicBrainz, одинаковые запросы от разных экранов объединяются.

- Успешный результат обновлять через **30 дней**. При временном сбое сохранять ранее полученный результат до успешного обновления или вытеснения.
- Уверенное отсутствие результата хранить **24 часа**. Отсутствие артиста обрабатывать до вызова внешнего источника.
- Тайм-аут, сетевой сбой, `429` и `5xx` считать временными ошибками. Повторять при обращении через **15 минут** либо позже, если сервер вернул больший `Retry-After`. Частичный результат остаётся доступен, например обложка при недоступной Wikipedia.
- После перезапуска накопленные результаты должны быть доступны офлайн. Ошибка кэша или внешнего источника не блокирует открытие страниц и управление плеером. Сбой записи диагностируется в логах без вывода путей библиотеки.

## Приёмка

| Проверка | Наблюдаемый результат |
| --- | --- |
| Adele *19*, *21* и Arctic Monkeys *Tranquility Base Hotel + Casino* | Карточки получают обложки. При воспроизведении видна та же картинка. `+` в названии на экране сохраняется |
| Локальная картинка, встроенная картинка, CUE и заглушка с HTTP 200 | Реальная картинка Volumio имеет приоритет. Встроенная картинка доступна при заглушке. CUE читается через связанный аудиофайл |
| *Forever Young* в нескольких изданиях | Исходные названия сохраняются. При подтверждённом американском издании выводится Atlantic. При совпадении только с группой лейбл пуст. Концертная запись не получает данные студийной |
| Исполнитель отсутствует либо найдено несколько одноимённых исполнителей | Локальная обложка работает. Для отсутствующего имени внешний поиск не вызывается. Неоднозначная биография скрыта |
| Три экрана и быстрая навигация | Каждый блок показывает справку нужной сущности. Запоздалый ответ не заменяет данные другой страницы или альбома |
| Повторный просмотр, перезапуск, офлайн и `503` | Общий кэш переиспользуется карточками и плеером. Ранее найденные данные доступны офлайн. Временный сбой не записывается как отсутствие совпадения |
| Большая сетка и стриминговый альбом | Запросы ограничены видимыми карточками и не блокируют UI. Для стримингов сохраняются действующие обложки и Info |

Автоматическими тестами покрыть распознавание локальной сущности и заглушки, сопоставление изданий, частичные результаты и сроки кэша. Сквозную проверку выполнить на Pi через карточку, страницы и реальное локальное воспроизведение.
