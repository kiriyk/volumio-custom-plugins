# Playback transports — первый этап Album Player

Общий транспорт для Qobuz Custom и Яндекс Музыки. MPD используется по умолчанию.
Штатные каталоги, авторизация и очередь Volumio сохраняются.

## Что реализовано

- MPD-транспорт с прежними командами и режимом consume.
- Album Player через локальный UPnP AVTransport: явные Stop / SetAVTransportURI /
  Play, pause/resume, seek в миллисекундах, получение состояния.
- Передача состояния от имени музыкального сервиса в CoreStateMachine.
  Автоматические переходы, repeat/shuffle остаются ответственностью Volumio.
- Защита от запоздавших результатов, двойного завершения, ранней ошибки
  воспроизведения и зависания в стартовом TRANSITIONING.
- Ошибочный SOAP-ответ, включая Fault с HTTP 200, отклоняется.

## Экспериментальное включение

Этот этап предполагает уже запущенный рендерер Album Player с известным
локальным controlURL. Его автоматический запуск, обнаружение после перезапуска,
общий экран настройки движков и управление профилями относятся к следующим этапам.

В каталоге конфигурации соответствующего плагина может находиться
`transport.json`:

```json
{
  "engine": "album_player",
  "controlUrl": "http://127.0.0.1:PORT/AVTransport/control.xml"
}
```

Путь controlURL берётся из description XML именно нужного экземпляра рендерера;
значения PORT и `/AVTransport/control.xml` здесь — пример, не фиксированный адрес.
Динамический UPnP-порт может изменяться после запуска рендерера.

Конфигурационные каталоги установленного плеера:

- `/data/configuration/music_service/qobuz_custom/`
- `/data/configuration/music_service/yandex_music/`

Настройки считываются при запуске плагина. Отсутствующий файл или
`{"engine":"mpd"}` оставляет MPD. Неправильный файл либо явный выбор
недоступного движка не маскируется автоматическим запуском другого выхода.
Постоянная конфигурация на пользовательском Pi этим этапом не изменялась.

Для установленного плагина используются собранные архивы из
`qobuz/scripts/package.sh` и `yandex-music/scripts/package.sh`: они копируют
общий исходный код в `lib/engines`. В монорепозитории адаптер читает
`shared/playback` напрямую. XML-парсер включён в зависимости обоих плагинов.

## Проверки

В корне монорепозитория: `npm ci && npm test`.
В `qobuz` и `yandex-music`: `npm ci && npm test`.

Приёмка на Raspberry Pi: `experiments/album-player/queue-acceptance.js` и
`queue-isolate.py`. Используются настоящий код очереди и CoreStateMachine
из установленного Volumio, отдельный `/data/queue` в mount namespace,
ALSA null и реальные потоки Qobuz. Основной MPD в этом прогоне не останавливается:
его release-вызов заменён заглушкой только внутри изолированного стенда.

HTTP-подача ограничивается по скорости, поскольку null не моделирует часы DAC.
Переходы альбома ускоряются seek к концу треков. Это подтверждает управление
очередью, но не непрерывное прослушивание полного альбома, gapless или bit-perfect.

## Следующие этапы

Постоянная служба рендерера и освобождение реального DAC; подключение локальной
библиотеки; общий переключатель MPD/Album Player. Для обоих движков сохраняются
два согласованных профиля: «Всё отключено» и «Пользовательские настройки».
Хранение и переключение этих профилей в продукте ещё не реализовано.

Команды SOAP имеют общий срок ожидания 15 с: нативное завершение декодера
при Stop может занимать более пяти секунд. Срок готовности нового потока —
20 с после подтверждения Play; зависание не приводит к бесконечному опросу.

Диаграмма тракта Artwork One в текущем интерфейсе ещё ориентируется на MPD;
её индикация не подтверждает параметры экспериментального Album Player.
