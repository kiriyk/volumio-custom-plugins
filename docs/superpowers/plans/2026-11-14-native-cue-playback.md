# Native CUE Playback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Удалить собственное производство WAV-сегментов и локальный HTTP-аудиомост;
воспроизводить CUE средствами выбранного MPD или полноценного Album Player,
с корректной очередью, перемоткой и переходами без искусственной подготовки треков.

**Architecture:** Volumio задаёт пользовательскую очередь и команды. Локальные
файлы открывает непосредственно выбранный нативный движок. Для потоковых источников
Album Player использует renderer. Переключение внутренних backend не добавляет
новых пунктов выбора движка в интерфейс. Автоматический переход AP внутри CUE
должен согласовываться с очередью до начала следующего трека, а не исправляться
запоздавшим Stop/повторным Play.

**Tech Stack:** Node/Kew, MPD 0.24.6 protocol, Album Player ARM32 2.20 HTTP API,
Python installer/discovery, systemd, ALSA; существующий React UI.

**Статус:** план реализации. Ни один пункт ниже ещё не считается выполненным.
Исследование: [результаты и первичные источники](../../research/2026-11-14-native-cue.md).
База реализации: `e9c723a` / Playback Engines 0.1.4.

## Итоговая схема

| Выбор / источник | Аудио открывает | Управление |
| --- | --- | --- |
| MPD / локальный файл или CUE | MPD, исходный файл/CUE | Нативный MPD transport |
| Album Player / локальный файл или CUE | Полноценный `aplayer` | Нативный AP transport |
| Album Player / Qobuz, Яндекс | `ap2renderer` | Существующий SOAP transport |

В локальном тракте отсутствуют сгенерированные WAV, PCM-кэш и HTTP-передача
локального аудио между процессами. Метаданные можно читать отдельно: это не
должно запускать подготовку аудио. Декодеры внутри MPD/AP остаются нативными.

## Обязательные условия

- Только выбранный backend открывает выбранный ALSA PCM; отсутствующий ЦАП
  не приводит к автоматическому выбору другого выхода.
- Существующие два режима и отдельные профили сохраняются. Bypass не меняет
  аппаратную громкость; предупреждение показывается при каждом входе в режим.
- Volumio не получает ложный EOF и не запускает уже играющий следующий трек заново.
- Смешанная очередь, duplicates, next/previous, repeat/shuffle не теряются молча.
- Не обрезать музыку таймерами, не генерировать заменяющие WAV/FLAC и не
  переключаться скрыто на другой движок при неподдержанном сценарии.
- На границах треков одного CUE с одинаковым форматом не останавливать процесс
  и не закрывать ALSA ради повторного preflight. Проверенный формат/файл можно
  переиспользовать в рамках актуальной сессии; изменение файла/выхода его инвалидирует.
- Новая ошибка не запускает следующий трек как будто предыдущий закончился.

## Review Focus

Пять проверок, которые легко упустить и которые привязаны к задачам ниже:

1. GetPlaylist завершился, но каталог ещё сканируется — ожидать готовности, а не
   сообщать о пустом CUE (этапы 1, 5).
2. Между CUE-1 и CUE-3 стоит другой источник — CUE-2 не должен заиграть до Stop
   из поллинга; изменения очереди и shuffle проверяются также (этапы 1, 5).
3. TRACK 03 — первый трек CUE, а title повторяется — ordinal/index и native
   revision должны выбрать правильную запись (этапы 2, 5).
4. Перемотка 30 секунд из 120 — native AP получает pos=25, не 30000 или 30;
   при неизвестной длительности запрос отклоняется (этапы 1, 4, 5).
5. Переход одного CUE при source format без изменений — нет повторного Play,
   закрытия PCM, порождённого WAV или буферизации всего образа (этапы 3–5, 8).

Для каждого кодового этапа 2–6: сначала новые тесты и подтверждённый FAIL,
затем минимальная реализация, повторный PASS и отдельный коммит. Исследовательский
этап 1 фиксирует реальные ответы и ограничения; он не требует боевого изменения.

## 3. Нативный локальный transport MPD

**Файлы:** новый `lib/native-mpd.js`, `tests/node/native-mpd.test.js`;
изменения `lib/manager.js` и real-core queue tests.

**Интерфейсы:** `NativeMpdTransport.play(descriptor, queueTrack, session)`;
`pause()`, `resume()`, `seek(ms)`, `stop()`, `close()`. Session содержит generation,
queueItemId и `isCurrent()`; повторяющиеся URI имеют разные queueItemId.
Manager использует отдельный `playLocal()` для descriptor, а существующий
потоковый `play(url, track, valid, owns)` не перегружается специальной CUE-строкой.

- [ ] Написать падающие тесты: MPD получает исходный путь/нативную CUE запись;
  в командах отсутствуют loopback WAV URL и запуск внешнего декодирования.
- [ ] Подключить native clear/add/play или проверенную native CUE queue операцию,
  сохранив обработку обоих URI, preflight, режимы и software mute.
- [ ] Нормализовать legacy cue:// форму для native prefetch, а не добавлять её
  в MPD вслепую как имя файла.
- [ ] Уточнить политику prefetch: разрешать только для проверенного native MPD
  локального пути. При Album Player MPD prefetch остаётся выключенным.
- [ ] Проверить реальные таймеры/EOF Volumio: native prefetch, core.currentPosition
  и события MPD должны двигаться согласованно без пропуска/повторного запуска.
- [ ] Проверить отмену уже начавшегося prefetch при Stop/смене движка/очереди.
- [ ] Пройти обычные файлы, CUE-альбом, смешанный источник и смену формата;
  отдельно измерить непрерывный PCM на соседних CUE-треках.

**Проверка:** `node --test playback-engines/tests/node/native-mpd.test.js`;
real-core queue tests с `VOLUMIO_STATEMACHINE_PATH` — PASS, затем нативная
интеграционная запись PCM.

**Результат:** MPD воспроизводит CUE собственным декодером без нашего аудиомоста.

## 5. Нативный AP transport и согласование очереди

- [ ] Сопоставлять нативный Song-change и логическую очередь один раз. Для уже
  играющего разрешённого следующего трека принять текущий native transport,

- [ ] EOF альбома, ручной Stop, ошибка и смена источника — разные события.

- [ ] Смешанная очередь, удаление/перестановка, дубликаты, repeat/shuffle обязаны

**Результат:** нативное чтение CUE через aplayer с согласованным управлением.
