# Исправление выбора ALSA-устройства в ap2renderer

## Причина и доказательства

На Raspberry Pi с Volumio 4 / Bookworm плагин выбрал `hw:CARD=NativeCueTest,DEV=0`,
но независимая проба `snd_pcm_open("default")` с конфигом рендерера вернула
физический Jack, ALSA card 1. С минимальным приватным конфигом та же проба
вернула тестовый card 7, device 0. Изолированный `ap2renderer` с этим конфигом
проиграл DSF → DFF → FLAC до EOF. В захвате были маркеры DoP для обоих DSD-файлов
и три участка по 44 100 кадров для FLAC. В Pi-пробе дополнительно ограничивали
доступ рендерера устройствами виртуальной карты.

[Runtime.startRenderer](../../../playback-engines/lib/runtime.js) импортирует
`/usr/share/alsa/alsa.conf` в приватный файл. В системной конфигурации есть
`@hooks` загрузки `/etc/asound.conf` и пользовательских настроек. libasound
выполняет эти hooks при обновлении дерева конфигурации. Они могут заменить
`pcm.default` уже после разбора приватного определения.
[Исходник ALSA](https://github.com/alsa-project/alsa-lib/blob/master/src/conf/alsa.conf) ·
[Документация hooks](https://www.alsa-project.org/alsa-doc/alsa-lib/confhooks.html).

Независимая проба на libasound 1.2.11 воспроизвела порядок загрузки без открытия
аудиоустройств. Импортированный тестовый hook заменил `pcm.default` с `hw` на
`null`. Без импорта дерево сохранило `hw` и `NativeCueTest`.

## Изменение

1. Обновить [тест генерации конфигурации](../../../playback-engines/tests/node/runtime.test.js).
   Проверять полное содержимое приватного файла, включая ALSA ID и отличный от
   нуля номер PCM-устройства. Старый код должен падать на этом тесте из-за
   импорта. Сохранить существующую проверку некорректного идентификатора
   устройства и запрета запуска сервиса после ошибки валидации.
2. Вынести общий генератор прямого ALSA-конфига из проверенной схемы
   [APlayer](../../../playback-engines/lib/aplayer-runtime.js) и использовать
   его для обоих процессов. Переиспользовать существующий `pcmParts`.
   Конфиг содержит только `pcm.!default` типа `hw` для выбранных card/device
   и `ctl.!default` типа `hw` для той же карты. У ALSA остаётся один явный
   адрес. При отсутствии или занятости устройства открытие завершается ошибкой.
3. Сохранить существующий путь приватного файла `asound.conf` и привязку
   через `ALSA_CONFIG_PATH` в
   [systemd unit](../../../playback-engines/systemd/volumio-playback-renderer.service).
   Проверить, что при смене устройства уже работающий рендерер останавливается
   до применения нового маршрута. Глобальные файлы ALSA не участвуют в правке.

Скоуп — маршрутизация `ap2renderer` для HTTP-источников, включая Qobuz и
Яндекс Музыку. Legacy CUE рендерера и границы CUE у MPD отложены. Поставляемые
бинарники, настройки выбора движка и сохранённые профили не требуют миграции.

## Приёмка

1. Прогнать Node-тесты Playback Engines и общих транспортов. Проверить оба
   генератора ALSA-конфигурации и выбор рендерера внешними источниками при
   локальном режиме APlayer. Собрать пакет и проверить его содержимое.
2. На Pi сначала использовать тестовую карту. Проверить конфиг реальным
   `snd_pcm_open("default", SND_PCM_NONBLOCK)` без записи семплов.
   `snd_pcm_info` должна вернуть заранее выбранные card и device при
   конфликтующем системном default. Повторить с другим PCM на виртуальной карте.
   Несуществующая тестовая карта должна дать ошибку открытия.
3. Проверить исправленный рендерер со штатным unit и конфигом из кода плагина,
   включая реальный `MainPID` и `ALSA_CONFIG_PATH` процесса. До Play проверить
   маршрут из шага 2. Запустить два HTTP-трека через Volumio и зафиксировать
   естественный EOF и переход в очереди. Сопоставить владельца PCM в
   `/proc/asound` с PID/Tgid рендерера и проверить закрытое состояние
   физических PCM во время теста. Захватить PCM и DoP на виртуальном устройстве.
   При наличии рабочих сессий Qobuz/Яндекс Музыки проверить по одному треку
   каждым провайдером через тот же маршрут.
4. Для рабочей установки использовать штатный update с резервной копией
   плагина и его настроек. После перезапуска подтвердить готовность через
   API Volumio. После проверки восстановить очередь и выбранный аудиовыход,
   снять временные ограничения и удалить виртуальную карту. При откате
   восстановить пакет и настройки из копии. Для воспроизведения до исправления
   проверенный маршрут на выбранное устройство остаётся у MPD.
