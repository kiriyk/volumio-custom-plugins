# Qobuz: исправления интерфейса, исполнители и скачивание

Пользователь явно поручил исправить крошки, качество, меню/иконки, добавить отдельный поиск с источниками под строкой и закончить исполнителей/скачивание. Каталог загрузок уточнён: `/media/External_HD/qobuz/исполнитель/альбом`, только при подключённом внешнем диске, без SD fallback.

Делаем расширение текущих плагинов, не перенос штатного упакованного Qobuz. Backend исполняется отдельной задачей по независимому контракту, root меняет Node/UI/установку. Поиск — существующий `/search` с постоянной кнопкой в desktop/mobile меню и кнопками источников, сохраняющими запрос. Крошки должны присутствовать при входе из поиска и при прямом открытии; уход из поиска сбрасывает его флаг. Определение Qobuz/Яндекса по стабильному URI при переписанном core поле service.

Страницы исполнителей: поиск, избранные исполнители, пагинируемая дискография, переходы из треков/альбомов. Не обещаем все треки исполнителя при отсутствии подтверждённого API.

Загрузки: один поток записи, ограниченная очередь, прогресс/отмена, оригинальный FLAC с базовыми тегами и подтверждённым качеством. Нормализованные компоненты путей, никаких symlink/path traversal и перезаписи существующего файла, атомарная публикация. Диск проверяется перед созданием и записью; отсоединение/нехватка места — явная ошибка. Обложки в этой итерации не записываются. Индекс MPD обновляется по факту завершения, очередь не меняется.

На exFAT файлы видны root:root/0755. Не отмонтировать диск и не менять его содержимое ради смены владельца. Служба остаётся User=volumio; минимальная CAP_DAC_OVERRIDE позволяет запись на том при существующем ProtectSystem=strict, с ограниченными writable путями конфигурации и `/media`. Проверки каталога в загрузчике обязательны. Системные изменения сохраняются в устанавливаемом unit плагина.

Проверки: воспроизводящие модульные тесты и один проход браузера по крошкам, источникам, меню и качеству; живой один трек на диск. Новую версию и архивы сохранить на GitHub. Перезапуск core может потребоваться для нового Node-кода: сначала проверить состояние и сохранить очередь; не прерывать активное воспроизведение без необходимости.
