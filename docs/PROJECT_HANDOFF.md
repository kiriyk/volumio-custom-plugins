## Каталоги и сохранность работы

- `volumio-yandex-music/` — Git-репозиторий плагина. Пользователь разрешил коммитить все текущие изменения. Перед дальнейшей работой смотреть `git status`, не откатывать чужие изменения.
- `volumio-artwork-one-custom/` — отдельный Git-репозиторий темы. Его origin — upstream автора, не хранилище пользовательской копии. Обновление темы из upstream может перезаписать наши доработки.
- При развертывании плагина использовать штатный update, а не uninstall/install: удаление стирает сохранённый вход. Пакеты предыдущих версий лежат в `volumio-yandex-music/dist/`.
- На Pi исправлена утечка D-Bus соединений в `volumiodiscovery`: при перезапуске mDNS исправлена ссылка `browse` на `browser`. Копия оригинала: `/data/volumiodiscovery-index-before-dbus-fix.js`. Восстановление: `volumio-yandex-music/scripts/repair-volumio-discovery.py`; это утилита изменения штатной прошивки, а не отдельный плагин. Ошибки DNS обнаружения могли оставаться; обновление Volumio может перезаписать исправление.
- Обход высокой загрузки CPU: для `volumio.service` установлен systemd drop-in `/etc/systemd/system/volumio.service.d/90-no-io-uring.conf` с `UV_USE_IO_URING=0`; на armhf / Node 20.5.1 / libuv 1.46.0 краткий замер снизился со 100% до 1,3% ядра. Откат: удалить этот drop-in, выполнить daemon-reload и перезапустить Volumio. Это обход проблемы, а не подтверждение её первопричины для всех версий.

## Следующие задачи

### Qobuz: независимый эксперимент 2026-11-10

Пользователь авторизовал браузерный вход. Прямой FLAC получен без штатного платного модуля Volumio: Get Lucky, ID 8767428, 247 секунд. Формат 6 — 16/44,1; запрос 27 вернул фактические 24/44,1 (format_id 7). ffprobe подтвердил оба варианта. Изолированный MPD 0.24.6 на порту 16601 подтвердил 44100:24:2, pause/resume, seek на 30 секунд и полное декодирование null-выходом без синхронизации примерно за 19 секунд. Текущая очередь и ALSA не менялись. Тестовый MPD и временный callback остановлены.

Сессия и параметры доступа сохранены только на Pi в `/data/qobuz-research` с закрытыми правами. Не выводить и не публиковать эти файлы. Истечение сессии не проверено. Экспериментальные скрипты без реквизитов и подробный отчёт находятся в `volumio-custom-plugins/experiments/qobuz/` и `docs/research/2026-11-10-qobuz.md` монорепозитория. Это ещё не устанавливаемый плагин. В callback обязательно принимать `code_autorisation`, а не только `code`.

Минимальный независимый `qobuz_custom` реализован и установлен. 17 Python и 4 Node-теста прошли, production-сборка темы и 5 UI helper-тестов прошли. Изолированный MPD через потоковый посредник установленного плагина подтвердил 24/44,1, pause/resume/seek и полное декодирование 247-секундного трека через null-выход примерно за 20 секунд. Основной Volumio не перезапускался, очередь и ALSA не менялись. Вход теперь хранится в `/data/configuration/music_service/qobuz_custom`; исследовательский резерв отдельно в `/data/qobuz-research`, оба приватные. На новой прошивке достаточно установить публичный пакет и пройти вход заново.

Следом — приёмка пользователем в браузере, затем коллекция/исполнители и отдельный этап скачивания. Кнопка скачивания пока не реализована. Сама локальная копия не улучшает FLAC; прямой MPD/ALSA может использоваться и для стриминга.

1. **Хранить резервную копию вне текущего компьютера.** Сохранить подготовленный комплект восстановления на отдельном носителе; не включать credentials и локальные секреты. После обновлений проверять совместимость Volumio и пользовательских изменений темы.
2. **Nova — исследование отдельной копии.** Nova уже расположена в `/data/nova/current` и зарегистрирована. README штатного `miscellanea/novaui` сообщает, что проверка подписки находится в интерфейсе и использует `pushSystemInfo` и `pushMyVolumioStatus`. Исследовать возможность отдельной копии и изменения локальной проверки без переустановки; работоспособность и удалённые зависимости не подтверждены. Artwork One сохранить как рабочую альтернативу.
3. **Сведения об исполнителях и альбомах.** Простые карточки с доступными данными Яндекса, MusicBrainz/Wikipedia, кэшированием и источниками. Учитывать одноимённых артистов и отсутствие описаний.
4. **Qobuz.** Первая версия установлена; расширять после пользовательской приёмки: полная коллекция, страницы исполнителей/дискография, скачивание отдельным этапом. Qobuz Connect — отдельная задача. Отчёт: `volumio-custom-plugins/qobuz/docs/testing.md`.
5. **Bit-perfect.** Проверить на устройстве тракт MPD/ALSA, микшер, ресемплинг, DSP и ЦАП. Спроектировать переключатель с сохранением/восстановлением настроек и отображением проверенного состояния; учесть риск изменения громкости. Не называть тракт bit-perfect без подтверждения.
6. **Умный поиск отложен пользователем.** Не начинать без нового запроса. Известно из заявления Volumio: Supersearch использует ИИ и сопоставляет предложенные треки с доступной библиотекой; собственный вариант может начинаться с локального индекса и поиска с опечатками.

Работать по этапам, проверять на устройстве, не нарушать пользовательскую очередь и текущее воспроизведение без необходимости. Предыдущий запрос пользователя: после этапа Яндекса остановиться и рассказать результат; этап принят пользователем.

## Обновление 2026-11-11: качество записей в каталоге, 0.2.2

Qobuz Custom и Яндекс обновлены до 0.2.2. В строках/плитках треков Artwork One выводится отдельная метка качества записи. Qobuz передаёт maximum_bit_depth/maximum_sampling_rate конкретного трека; отсутствующие данные не подменяются максимумом альбома. Максимум альбома выводится на его карточках, включая дискографию исполнителя. Метаданные записи не заменяют фактическое качество проигрываемого потока.

Яндекс не отдаёт качество в каталоге: видимые треки запрашивают новый getRecordingQuality → локальный /v1/tracks/{id}/quality. Сервер проверяет file-info, при необходимости варианты MP3 без получения прямых ссылок и без загрузки аудио. В UI передаются только codec/bitrate/basis, без URL и токенов. Кэш сервера 512 записей/1 час, проверки последовательные; браузер ограничен двумя запросами и очередью 64, успех 1 час, ошибка 5 минут. Яндекс показывает FLAC либо MP3 с подтверждённым битрейтом, без неподтверждённой разрядности/частоты.

Исправлены подписи «1 album · 5 tracks» у локальных песен после перехода от исполнителей к альбому: счётчик теперь хранит URI владельца и показывается только на соответствующем artists:// folder. Раньше React повторно использовал компоненты с ключами по позиции, сохраняя чужой countMeta/counts в useState.

Проверки: 47 Python Qobuz, 54 Python Яндекс, 9 Node Qobuz, 33 Node Яндекс и 16 UI helper tests; production-сборка. Первые Node-запуски потребовали подключения существующих зависимостей/venv к worktree; зависимые проверки повторно прошли. .venv игнорируется также как symlink. Живой API подтвердил FLAC Яндекса и 16/44.1, 24/88.2 Qobuz. Браузер подтвердил метки Qobuz в светлой теме.

На Pi обновлены исходники/пакеты/тема; Volumio перезапущен во время паузы, Python-службы отдельно перезапущены для загрузки кода. Все 23 URI очереди и выбранный локальный трек сохранились. После перезапуска status=stop; аудио не запускалось. Резерв предыдущих исходников: /data/catalog-quality-backup-0tgyocjg. Новые архивы проверены Gitleaks: только известная публичная Firebase-конфигурация, действующих реквизитов в пакетах не обнаружено.
