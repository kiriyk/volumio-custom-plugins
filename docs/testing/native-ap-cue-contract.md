# Нативный Album Player: проверка границ CUE

Дата: 2026-11-14. Volumio 4.239, Raspberry Pi 4, ARMHF, официальный Album
Player for Linux 2.20. Это первый gate плана
[нативного CUE](../superpowers/plans/2026-11-14-native-cue-playback.md),
а не готовый боевой адаптер.

**Решение: NO-GO для замены текущего адаптера с сохранением произвольной очереди
Volumio.** Подтверждён нативный выбор CUE-трека, но не поддерживаемое ограничение
конца выбранного трека. Единственный трек в сохранённом плейлисте не ограничивает
вывод его объявленной длительностью. Нужен другой контракт с движком или явное
изменение требований. Рабочий мост и установленные плагины здесь не изменены.

## Что проверено звуком

Источник — самостоятельно сгенерированный FLAC 44,1 кГц, stereo, 16 bit,
30 секунд: значения семплов 1, 2, 3, каждое по 10 секунд. CUE содержит
One/Two/Three с INDEX 01 00:00:00, 00:10:00, 00:20:00.
Это искусственные маркеры, а не музыкальные материалы пользователя.

Вывод направлен в отдельный `snd-aloop`, card7, ID `NativeCueTest`, device0;
`arecord` читает device1 в S32_LE/44100/stereo. Никакой физический DAC/HDMI
не используется. Все тесты начинались с нового приватного процесса aplayer.

| Сценарий | Метаданные API | Фактический PCM | Результат |
| --- | --- | --- | --- |
| Нативная папка, Play song=2 | Three, 10000 мс | Только маркер 3, около 10 с | Выбор начала работает |
| Экспорт AP3, только первый трек | One, 10000 мс | 1 → 2 → 3, около 30 с | Конец не ограничен |
| Экспорт AP3, только третий трек | Three, 10000 мс | Только 3, около 10 с | Это конец файла, не доказательство ограничения трека |
| Экспорт AP3, порядок 3 → 1 → 3 | Три записи, каждая 10000 мс | 3 → 1 → 2 → 3, около 40 с | Воспроизводится лишний второй трек |

AP3 здесь — экспериментальное редактирование метаданных, сохранённых штатной
командой SavePlaylist, а не документированное API произвольной очереди. Этот
эксперимент опровергает пригодность именно такой схемы. Он не доказывает, что
никакого другого механизма внутри закрытого движка не существует.

Контрольный неизменённый экспорт 3×2 секунды воспроизводит 1 → 2 → 3.
Но выбор третьего трека в таком коротком FLAC неожиданно начинался с начала
файла. На 30-секундном источнике выбор третьего работает. Причина зависимости
от короткого источника не установлена; короткая фикстура исключена из главного
вывода. Захват содержит короткие нулевые участки возле конца; это не доказательство
ни безупречного gapless, ни ошибки реального DAC. Точность последнего семпла,
форматы реального устройства и bit-perfect этим тестом не сертифицируются.

Обезличенные JSON результатов лежат в
[`tests/native/fixtures`](../../playback-engines/tests/native/fixtures).

## Проверяемые API и ограничения

Официальные источники:
[архив ARM32](https://albumplayer.ru/linux/aplayer-arm32.tar.gz),
[руководство Linux 2.20](https://albumplayer.ru/linux/album_player_linux_manual_ru.pdf),
штатный `aplayer.js` внутри архива.
SHA256 архива: `6f05109b597f9e0425a1f01f92109725daa30a66e8f2ef4a0274c7add4806f38`.

- GetPlaylist запускает асинхронное сканирование. Перед Play нужны
  `State.Scanning=false` и непустой GetAlbums.
- GetSongs возвращает названия/длительности, GetPath — исходный файл. Один файл
  не идентифицирует конкретный CUE-диапазон.
- `State.Position`, `PlayingLen`, `SongsLen` — миллисекунды. Position&pos задаёт
  процент; их нельзя смешивать.
- State.Song/Album — адреса в текущем нативном плейлисте; после изменения/сканирования
  они не являются постоянными идентификаторами. Будущий nativeRef требует
  `{playlistRevision, albumIndex, songIndex}` и отдельного source descriptor.
- `auto_mode=false` запрещает следующий альбом, но внутри CUE следующий трек
  продолжает играть. Это согласуется с руководством, раздел General.
- В изученных GetConfig и официальном JS не найдено single/oneshot/stop-after-track
  или параметра конечного времени для Play. Угадывать недокументированные команды
  и считать их работающими нельзя.
- Плейлист с одним треком может показывать `PlayingLen=10000`, хотя Position
  доходит до 30000 и PCM содержит весь исходник. UI и State недостаточно для
  доказательства корректного тракта.

Не проверены до завершения gate: повторы/shuffle/редактирование смешанной очереди,
отмена сканирования, одинаковые названия, несколько CUE/FILE в каталоге,
все профили после перезапуска, pause/seek на всех форматах. Полный контракт
NativePlayerState и боевой автомат очереди пока не утверждены.

## Повторение на изолированном экземпляре

Проверки самого инструмента: `python3 -m unittest discover -s playback-engines/tests/native -p 'test_*.py'`
(3 проверки: устаревший список до Play, очистка после выхода AP, зависший recorder).

Тест опциональный, в обычный npm test не входит. Требуются штатный snd-aloop,
arecord и уже запущенный aplayer из приватного `/tmp/.../player/aplayer`.
Используйте короткий корень: в отдельном эксперименте длинный root_folder
после сохранения/перезапуска оказался повреждён; предел длины не установлен.
Не используйте рабочий процесс или каталог плеера.

1. Создать отдельный временный каталог с `player` и `music/CUE`. Скопировать туда
   официальный aplayer. Сгенерировать источник приведённым ниже кодом, преобразовать
   `seed.wav` в `music/CUE/original.flac` через ffmpeg. WAV должен остаться вне
   сканируемой папки. Это генерация тестовой фикстуры, не аудиомост.
2. Загрузить тестовую виртуальную карту, если snd-aloop ещё не используется:
   `sudo /sbin/modprobe snd-aloop index=7 id=NativeCueTest pcm_substreams=1`.
   При занятости card7 прекратить тест, не выбирать другой реальный выход.
3. Создать приватный ALSA_CONFIG_PATH с ровно такой конфигурацией:

   ```text
   pcm.!default { type hw card "NativeCueTest" device 0 }
   ctl.!default { type hw card "NativeCueTest" }
   ```

   Не включать `/usr/share/alsa/alsa.conf`: его глобальные hooks могут подгрузить
   `/etc/asound.conf` и заменить default. Это воспроизведено на текущей системе.
4. Запустить aplayer из приватного player с этим ALSA_CONFIG_PATH. В собственной
   конфигурации выбрать `cue_mode=true`, `auto_mode=false`, `di_mode=0`,
   `gapless_mode=true`, `preload_mode=false`, `volume_enabled=false`,
   `hw_volume=false`; root_folder должен указывать на тестовый music.
   Запись через SetConfig должна повторять writable-поля официального JS, не
   переносить stat_* поля. Перезапустить только этот процесс после настройки.
5. Определить PID именно дочернего демона: первоначальный процесс может fork-нуться.
   Передать явный адрес и PID. Каждый HTTP-запрос повторно проверяет executable,
   start time PID, принадлежащий ему listener7778 и приватный ALSA default:

   ```bash
   python3 playback-engines/tests/native/native-ap-cue-contract.py \
     --pid "$NATIVE_TEST_PID" --executable "$NATIVE_TEST_ROOT/player/aplayer" \
     --url http://127.0.0.1:7778 --folder "$NATIVE_TEST_ROOT/music/CUE" \
     --case one --report "$NATIVE_TEST_ROOT/one.json"
   ```

   Сценарии: direct, direct-last, exported, one, third, reordered. Для каждого
   запускать новый приватный процесс. Код 0 означает совпадение порядка PCM-маркеров
   в этом сценарии; 1 — несовпадение, 2 — неподходящее окружение. Это не общий GO
   и не проверка точного количества семплов. Сейчас one/reordered должны дать 1.
6. Тест удаляет собственный capture и созданные им AP3. Остановить свой приватный
   aplayer. Если карту загрузили именно для этого теста и пользователей больше нет,
   выполнить `sudo /sbin/modprobe -r snd-aloop`. Рабочий движок/выход не менять.

Генератор WAV и CUE (запускать в тестовом корне):

```python
from pathlib import Path
import struct
import wave

album = Path('music/CUE')
album.mkdir(parents=True, exist_ok=True)
with wave.open('seed.wav', 'wb') as output:
    output.setnchannels(2)
    output.setsampwidth(2)
    output.setframerate(44100)
    for marker in (1, 2, 3):
        output.writeframes(struct.pack('<hh', marker, marker) * 44100 * 10)
(album / 'album.cue').write_text(
    'TITLE "Native Contract"\nPERFORMER "Test"\nFILE "original.flac" WAVE\n'
    ' TRACK 01 AUDIO\n TITLE "One"\n INDEX 01 00:00:00\n'
    ' TRACK 02 AUDIO\n TITLE "Two"\n INDEX 01 00:10:00\n'
    ' TRACK 03 AUDIO\n TITLE "Three"\n INDEX 01 00:20:00\n')
```

## Дальнейшие варианты

1. Сохранить полную очередь Volumio: для нативного AP нужен подтверждённый контракт
   диапазонов/точной очереди, изменение самого движка или другой движок.
2. Явно принять альбомную семантику AP: CUE проигрывается последовательно до конца
   исходного файла. Смешанные очереди/повтор одного внутреннего трека/shuffle требуют
   ограничений в UI. Это изменение согласованного объёма, а не готовая замена.
3. Отдельно реализовать нативный MPD, который уже предоставляет CUE Range.
   До появления решения для AP общий мост нельзя просто удалить: это сломает
   текущий доступ к локальным файлам через renderer.

Таймерный Stop и скрытое переключение на MPD не устраняют ограничение и не входят
в предложенную реализацию.
