# Album Player как второй движок Volumio: эксперимент 2026-11-11

## Результат

ARM32 Album Player и его UPnP-рендерер запускаются на имеющемся Raspberry Pi
с Volumio 4.239 / armhf. Через рендерер подтверждены передача URL от нашего
Qobuz Custom, декодирование FLAC, pause/resume, seek с HTTP Range-запросами
и явная смена трека командой SetAVTransportURI + Play.

Для дальнейшей интеграции предпочтителен рендерер с нашей очередью Volumio.
Это проверка технической возможности, не установленный переключатель движков.

Пожелание пользователя: у **каждого** движка два профиля обработки:

- MPD: всё отключено / пользовательские настройки.
- Album Player: всё отключено / пользовательские настройки.

## Изоляция и исходные материалы

Проверка выполнялась в `/tmp/albumplayer-research` на Pi. В отдельном mount
namespace `/etc/asound.conf` заменялся на ALSA null, `/dev/snd` скрывался.
После подготовки плеер запускался от UID/GID 1000. Сеть оставалась общей
для доступа к loopback-посреднику Qobuz. Основные службы не перезапускались.

Хеш playlistinfo, состояние pause, позиция 12.109 с и громкость 86 основного
MPD до и после совпали. Эксперимент не подтверждает физический звук,
bit-perfect, бесшовность или поведение USB DAC.

## Профили обработки

У локального плеера и у рендерера проверено сохранение пользовательского
профиля (пример: res44=2, то есть 48 кГц, и volume_enabled=true), применение
профиля без обработки и восстановление пользовательских значений.
Результаты проверялись повторным GetConfig, а не только HTTP-кодом.

Для проверенного PCM-профиля отключались:

- volume_enabled, hw_volume;
- use_conv;
- mode_16bit, mode_24bit — принудительные ограничения разрядности;
- phase_mode, swap_mode, multi_mode;
- enable_dsd — преобразование PCM в DSD;
- res_bf44, res44, res48, res88, res96, res176, res192, res352, res384 = 0
  (original в штатной форме).

Обязательные буферы и gapless не являются обработкой отсчётов; выключать
их по названию «всё отключено» не нужно. Пользовательский профиль должен
храниться отдельно от активного, иначе отключение обработки уничтожит
его значения. DSD/DoP, автоматические fallback и отказ при неподдерживаемом
формате отдельно не проверены; строгий профиль для них ещё не определён.

Особенность рендерера: отправка полного ответа GetConfig в SetConfig
возвращала HTTP 200 с телом `Settings not saved!`. Сохранение заработало
после формирования запроса по набору полей штатного renderer.js.
Поэтому HTTP 200 нельзя принимать за подтверждение сохранения;
нужны проверка ответа и чтение значений обратно.

## Локальный aplayer

- Работают State, GetConfig, GetAlbums, GetPlaylists и загрузка папки.
- Локальный Get Lucky распознаётся с длительностью 247632 мс.
- M3U с потоковым URL в исследованном сценарии загрузки папки не стал
  отдельным треком: в альбом попал только локальный FLAC.
- Через AddStation удалось передать URL от нашего Qobuz-посредника.
- Фактический вход: FLAC 24 бит / 44.1 кГц, выход в null: S32_LE / 44.1 кГц.
- Pause меняет состояние. Но в радиорежиме длительность — условные
  35999999 мс, поэтому seek в процентах не даёт надёжной привязки к треку.

Вывод: радиорежим подходит для проверки декодирования URL, но не выбран
основой адаптера очереди.

## UPnP-рендерер

Использовался именно тестовый ap2renderer: его UPnP HTTP-порт определялся
по сокетам собственного процесса, controlURL — из description.xml.
Команды посторонним рендерерам не отправлялись.

| Проверка | Наблюдение |
| --- | --- |
| SetAVTransportURI + Play | FLAC 24/44.1 декодируется, выход S32_LE/44.1 |
| Длительность | 0:04:07 вместо условной длительности радио |
| Pause | PAUSED_PLAYBACK |
| Seek на 30 секунд | RelTime=0:00:30; в trace появились ненулевые HTTP Range-запросы |
| Resume | PLAYING |
| SetNextAVTransportURI + Next | SOAP без ошибки, но второй URL не запрошен, состояние STOPPED |
| Явные Stop + SetAVTransportURI + Play | Второй URL запрошен; FLAC 24/88.2; выход S32_LE/88.2; PLAYING |
| Автоматический переход после seek к концу | Второй URL запрошен и декодирован; итог STOPPED и несогласованные URI/метаданные |

Треки: Get Lucky (8767428) и Give Life Back to Music (9140024).
Смена 44.1 → 88.2 кГц подтверждена на виртуальном выходе. Физическое
переоткрытие DAC на другой частоте не проверялось.

Для seek в сетевой трассе наблюдались диапазоны около 6 МБ после перехода
к 30 секундам; исходный FLAC имеет около 51.5 МБ. Это дополнительное
подтверждение сетевого перемещения, помимо изменения поля позиции.

Нельзя считать SetNextAVTransportURI/Next готовым механизмом очереди.
Нельзя считать последний STOPPED доказательством неисправности физического
воспроизведения: null не моделирует временное поведение DAC. Тем не менее
согласованное управление переходами и метаданными остаётся неподтверждённым.
Аудиобесшовность не измерялась.

## Предлагаемый путь реализации

1. Очередью, shuffle/repeat и выбором следующего URI продолжает владеть Volumio.
2. Вынести транспорт из текущих Yandex/Qobuz Playback в общий интерфейс.
   Существующие разрешение URL и авторизация сохраняются.
3. Для Album Player использовать отдельный транспорт к ap2renderer;
   ручные переходы выполнять явной передачей нового URI.
4. Не полагаться на штатный Next и reported CurrentURI без дополнительной
   проверки; выбранный трек хранить в адаптере.
5. Сначала надёжно реализовать одиночное воспроизведение и последовательные
   переходы; gapless оставить отдельным неподтверждённым свойством.
6. Профили обработки хранить по движкам. При смене движка останавливать
   прежний вывод и подтверждать освобождение устройства.
7. На реальном DAC проверить форматы, unsupported-format policy, поведение
   громкости, stop/pause, смену частоты и отсутствие обработки отсчётов.

UI переключателя, постоянная служба и интеграция Volumio в этом эксперименте
не изменялись. Проверены экспериментальные скрипты и фактические ответы
ARM-бинарников; основной регрессионный набор проекта не требовался,
поскольку продуктовый код не менялся.
