# Приёмка первого этапа Album Player

Дата: 2026-11-11. Ветка: `feat/album-player-transport`.

## Готовый результат

Общий транспорт MPD/Album Player подключён к Playback Qobuz и Яндекса.
По умолчанию поведение MPD сохраняется. Экспериментальное подключение
Album Player задаётся отдельным transport.json при запуске плагина.
Постоянная установка и настройки на Pi не изменялись.

## Автоматические проверки

- Общий транспорт: 13 Node-тестов.
- Qobuz: 12 Node-тестов.
- Яндекс: 35 Node-тестов.
- Архивы обоих плагинов содержат `lib/engines`; в отдельных каталогах за
  пределами монорепозитория выполнены npm ci и загрузка обоих транспортов
  и контроллера плагина. Родительский shared-каталог им недоступен.
- Независимое ревью обнаружило гонку pause во время запуска и бесконечное
  ожидание TRANSITIONING. Оба случая сначала воспроизведены HTTP-тестами,
  затем исправлены. Ревью исправлений не выявило важных замечаний.

- Проверки установщика/упаковки Яндекса: 6 Python-тестов.

## Реальная ARM-приёмка

Выполнена на существующем Raspberry Pi / Volumio 4.239, armhf.
Использовались новый production-код транспорта, настоящий ARM ap2renderer,
реальный Qobuz-посредник с текущей сессией и CoreStateMachine/PlayQueue
из установленного Volumio. Сетевые и SOAP-ответы не имитировались.

Изоляция: отдельный mount namespace, ALSA null, скрытый /dev/snd,
приватная копия /data/queue. Контроллер публикации UI/сохранения состояния
в стенде заменён тестовым, а release MPD — заглушкой, чтобы не останавливать
основной плеер. Это не проверка работы из установленного браузерного интерфейса.

Альбом: **Daft Punk — Random Access Memories**, 13 треков.

| Сценарий | Результат |
| --- | --- |
| Запуск первого трека | Пройдено |
| Pause/resume через CoreStateMachine | Пройдено |
| Seek на 30 с | Получена позиция 31 с после следующего опроса |
| Следующий трек через очередь Volumio | Пройдено |
| Предыдущий трек через очередь Volumio | Пройдено |
| Автоматические переходы | Все 12 пройдены |
| Окончание последнего трека | Штатная остановка |
| Ошибки транспорта | Нет |

Переходы ускорены seek к концу каждого трека. Из-за отсутствия часов
реального ALSA-устройства HTTP-подача ограничивалась по скорости.
Первый прогон без ограничения подачи прошёл play/pause, но не resume;
после моделирования подачи по времени полный сценарий прошёл.
Это не результат непрерывного прослушивания полного альбома и не измерение gapless.

Повторная короткая приёмка финального кода на двух треках также прошла:
play/pause/resume/seek/next/previous, автоматический переход и остановка
очереди. Результат: `experiments/album-player/queue-smoke-result.json`.

При её подготовке выявилась медленная отработка Stop в нативном рендерере
при быстром возврате к предыдущему треку. Исходный срок ожидания команды 5 с
оказался недостаточным. Исправлено с отдельными RED→GREEN HTTP-тестами:
команда ожидается ограниченные 15 с, а 20-секундный срок готовности потока
отсчитывается после подтверждения Play. Повторная ARM-приёмка прошла без ошибок.

Машиночитаемый результат: `experiments/album-player/queue-result.json`.
Исходник стенда: `queue-acceptance.js`; подготовка изоляции: `queue-isolate.py`.

## Сохранность основного плеера

Сравнение снимков до/после подтвердило совпадение:

- хеша содержимого очереди MPD;
- паузы, позиции 12.109 с, громкости 86 и идентификаторов MPD;
- хеша основной `/data/queue` Volumio;
- хеша `/etc/asound.conf`.

Секреты и временные потоковые URL в результаты и репозиторий не копировались.

## Границы этапа

Yandex прошёл автоматические тесты адаптера, но живой поток Яндекса через
Album Player в этом этапе не проверялся. Физический DAC, bit-perfect,
бесшовность, UI выбора движка, профили обработки и локальная библиотека
остаются следующими этапами. Сам рендерер не устанавливался как постоянная служба.
