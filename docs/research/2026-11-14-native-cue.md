# Нативное воспроизведение CUE: результаты исследования

База: `e9c723a`, Playback Engines 0.1.4. Исследование не меняет рабочий плагин,
очередь, профили и выбранный ALSA-выход. Временные экземпляры aplayer запускались
отдельно с приватным ALSA `null`, без команд воспроизведения.

## Подтверждено

1. Установленный MPD 0.24.6 собран с `cue` и `embcue`. Read-only команда
   `listplaylistinfo` для настоящего Adele — 30 CUE возвращает исходный FLAC,
   названия треков и `Range`: первый `0.000–182.160`, второй
   `182.160–406.853`. Это нативные записи плейлиста, а не WAV-сегменты.
2. Volumio 4.239 содержит `explodeCue()` и ветку `clearAddPlayTrack()` для
   `cue://…@index`: `stop → clear → load CUE → play index`. Другой вариант URI
   библиотеки — `music-library/…cue/track0001`. Их индексацию нельзя смешивать.
3. Debian Live из соседнего AlbumPlayerDebian запускает полноценный `aplayer`.
   Его `web/volumio/player-api.js` использует `GetPlaylists`, `GetPlaylist`,
   `GetAlbums`, `GetSongs`, `Play&album=…&song=…`, `State`, `Position`, `Next`,
   `Prev`, `Pause`, `Stop`. Готовый адаптер полезен как описание протокола;
   переносить целиком его UI, сервисы или x86-бинарник не требуется.
4. Официальный полноценный Album Player доступен для ARM32. Архив загружен
   отдельно, проверен как ELF32 little-endian ARM; нативный HTTP API запущен на Pi
   во временном каталоге. `cue_mode=true` доступен. После загрузки тестовой папки
   с одним исходным WAV и CUE он вернул Part One/Two/Three, по 2000 мс каждый.
   `Playing=false`: загрузка библиотеки сама не включила воспроизведение.
   Дополнительно этот же ARM32 aplayer напрямую прочитал настоящий Adele — 30:
   15 треков, первый Strangers By Nature длительностью 182160 мс; Scanning=false,
   LastError пустой, Playing=false. Ни одного сгенерированного аудиосегмента нет.
5. В руководстве есть отдельные Standard, Direct Input, Full Memory; gapless;
   использование CUE; переход на следующий альбом. Для первой реализации
   подходит Standard без автоматического Full Memory, с проверкой gapless.
6. Текущая интеграция использует `ap2renderer`, получает HTTP URL и не использует
   нативный каталог полноценного aplayer. Собственный WAV-кэш — следствие этой
   архитектуры, а не отсутствие CUE в Album Player/MPD.

## Важные ограничения и непроверенные контракты

- GetPlaylist возвращается до окончания сканирования. Немедленный GetAlbums
  для настоящего FLAC+CUE первоначально был пустым; после ожидания Scanning=false
  появились все 15 треков. Пустой промежуточный ответ не является ошибкой CUE.
- State.Position/PlayingLen/SongsLen — миллисекунды, а запрос Position&pos=…
  задаёт проценты. Это разные единицы, как и в адаптере Debian Live.
- В изученных штатном JS и GetConfig нет подтверждённого управления «остановиться
  после конкретного трека». `auto_mode` управляет переходом между альбомами;
  считать его запретом следующего трека внутри CUE нельзя.
- Нативный AP имеет собственные альбомы/индексы и автоматически переходит между
  треками. Поддержка произвольной смешанной очереди Volumio, повторов,
  shuffle и изменений очереди на лету ещё не доказана. Нельзя подменить её
  таймером Stop на границе: это не обеспечивает корректность перехода.
- GetSongs показывает названия/длительности, но этого недостаточно для стабильной
  идентичности файла. Одинаковые названия и несколько CUE в одной папке требуют
  отдельной проверки сопоставления.
- Для локального AP нужна собственная сериализация SetConfig по штатному SaveConfig,
  а не GetConfig целиком или whitelist renderer. В изолированном ARM32-пробнике
  короткий `root_folder` сохранился корректно, длинный после перезапуска исказился.
  Причина/точный предел не установлены; проверять запись и повторное чтение после
  перезапуска. Не задавать длинные пути библиотеки через этот параметр вслепую.
- В исходнике MPD 0.24.6 CUE-позиции переводятся в целые миллисекунды. Строка
  Range не доказывает sample-exact границу. Не восстанавливать аудиосегменты
  самостоятельно из округлённых строк; поведение движка проверять PCM-записью.
- В этой исследовательской сессии аппаратное воспроизведение через FiiO,
  бесшовность и полная семантика очереди не проверялись.
