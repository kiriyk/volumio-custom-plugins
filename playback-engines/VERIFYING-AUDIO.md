# Проверка аудиотракта

Надпись «Всё отключено» показывает выбранный профиль. Она не является независимой
проверкой цифровых отсчётов. Проверять нужно отдельно конфигурацию, открытый выход
и фактические параметры потока во время воспроизведения.

## 1. Контрольный файл и фактический PCM

Используйте FLAC или WAV с известными параметрами: например, 16 бит / 44,1 кГц,
затем 24 бит / 96 кГц, если устройство поддерживает этот формат. В bypass частота
и число каналов должны сохраняться. 24-битные отсчёты могут передаваться в
32-битном контейнере без потери точности; одна надпись S32_LE не доказывает
повышение исходной разрядности или изменение сигнала.

На Pi во время воспроизведения:

```bash
cat /proc/asound/cards
```

Найдите выбранное устройство. Для текущего встроенного Headphones это card1,
PCM device 0. Для USB ЦАПа номер может быть другим:

```bash
cat /proc/asound/card1/pcm0p/sub0/hw_params
cat /proc/asound/card1/pcm0p/sub0/status
```

В hw_params интересуют rate, channels, format. В status — RUNNING и owner_pid,
если ядро выводит это поле. Проверьте процесс владельца через `ps -p PID -o comm=`:
ожидается mpd для MPD или ap2renderer для Album Player. Если hw_params показывает
closed, устройство сейчас не открыто; по этому состоянию нельзя проверить формат
во время игры. Проверяйте также другие sub-потоки, если выбранный не открыт.

USB устройства могут дополнительно показывать активный интерфейс/формат в
`/proc/asound/cardN/stream0`, если такой файл существует. Индикатор частоты на
ЦАПе — полезная дополнительная проверка, но не доказательство bit-perfect.

[Документация ядра Linux по ALSA procfs](https://kernel.org/doc/html/v6.14/sound/designs/procfile.html)
описывает hw_params как фактически установленные аппаратные параметры потока,
status как его состояние, а stream* как информацию о USB audio.

## 2. Что должно соответствовать профилю

| Проверка | MPD bypass | Album Player bypass |
| --- | --- | --- |
| Процесс, открывший PCM | mpd | ap2renderer |
| Вывод | выбранный прямой hw: | приватный default типа hw, выбранная карта/device |
| Громкость движка | mixer_type none | volume_enabled=false, hw_volume=false |
| Ресемплинг | нет принудительного format | все res* = 0 |
| Дополнительная обработка | ReplayGain off, crossfade 0, нормализация выключена | convolver, phase, swap, downmix, forced bits выключены |
| Другие выходы MPD | только Playback Engines включён | все выходы MPD отключены |

Конфигурацию MPD можно читать в /etc/mpd.conf. Его runtime ReplayGain/crossfade
и список активных выходов проверяются через протокол MPD, а не только этот файл.
Album Player нужно проверять через GetConfig именно управляемого процесса:
плагин обнаруживает его API по сокетам MainPID своей systemd-службы, отправляет
профиль и сверяет ответ чтением назад. Текущий UI показывает выбранный профиль
и готовность; фактические hw_params и процесс-владелец в UI пока не выведены.

В custom для проверки управления можно явно задать 48 кГц и воспроизвести файл
44,1 кГц: аппаратный поток должен стать 48 кГц. Верните нужный профиль после
проверки; в bypass преобразование неподдерживаемого формата не должно происходить.

Для MPD полезна дополнительная проверка verbose-лога: сравнить `decoder: audio_format`,
`output: ... audio_format` и наличие `output: converting`. Это описано в
[официальном руководстве MPD](https://mpd.readthedocs.io/en/stable/user.html#bit-perfect-playback).
Включение verbose и перезапуск для такой проверки выполняются отдельно: текущая
проверка ничего не перезапускала и музыку не запускала.

## 3. Граница доказательства

Настройки, процесс-владелец и совпавший формат подтверждают маршрут и отсутствие
неожиданного изменения формата. Они не обнаружат любое изменение громкости,
дизеринг или обработку, сохраняющую формат.

Независимая проверка bit-perfect — цифровой захват сигнала до аналогового
преобразования и сравнение PCM-отсчётов с эталоном после выравнивания задержки и
упаковки. Сам тракт захвата тоже должен быть без регулировки/ресемплинга. Сравнивать
нужно PCM, не файлы FLAC с разными метаданными. Альтернатива — встроенный bit-test
ЦАПа, если конкретный ЦАП его поддерживает. Для аналогового Headphones такой
побитовой проверки на выходе нет; совпадение частоты в ALSA не проверяет аналоговую
часть или внутреннее преобразование аппаратуры.

Для Album Player это особенно важно: его нативный движок закрыт, поэтому нельзя
подменять измерение вывода чтением флагов. До независимой проверки плагин не
показывает подтверждённый bit-perfect.
